# 环境统一及流程修复记录

## 已实现

- 操作台的四个测试/正式启动器都调用 `pipeline.py`，按平台选择同一份计算源码，按环境选择独立数据与连接配置。UPB 不再从 Desktop 执行独立代码副本，UPW 的计算配置也统一。
- UPW/UPB 同步共用 `sync_common.py`。读取遇到 429、502 等临时错误自动重试；上传响应不确定时先读回核对，不自动重复 POST。
- 云端验收从“最新日期相同”加强为每天、BD、代理及类别的金额/卡数一致、月目标一致；网站数据与已验收云端内容一致。
- “仅验收”入口不重算、不上传；可恢复同版本、同结果的未完成发布验收记录。
- “发布测试结果”入口校验代码摘要、结果校验值和成功记录，原样发布已测 CSV；先备份原正式输出。测试验收不自动触发正式发布。
- 锁按环境生效，避免 UPW/UPB 同时写同一 Apps Script。操作系统释放锁，避免异常关窗留下永久阻塞。
- 测试先准备输入再计算，消除了首次运行因旧测试副本不存在而失败的问题。沿用用户已明确的公开真实汇总数据授权。
- 过滤指定的 Excel 缺默认样式提示；保留真正错误。按阶段显示耗时，记录日志与 JSON 运行结果；日志、临时锁和 Python 缓存排除出 Git。
- Apps Script staging 从正式核心生成，去除独立汇总算法。修复日期型月份目标、Wallet 最近一天金额汇总，统一 Unassigned 合并行为；测试接口版本 7 已部署。
- 更新 README、操作台和日常手册中旧入口、错误日志目录及 UID 匹配描述。

## 验证和发布边界

17 项 Python 检查及 4 项 JavaScript 检查通过，覆盖重复订单、环境误配、502 恢复、验收内容、锁释放、发布后改文件及两环境汇总一致性。

使用真实 staging 数据执行完整 UPW/UPB 计算与上传；本次输入截止 2026-09-24。正式环境仅执行读回验收，没有上传新数据或部署新云端代码。

云端正式 Apps Script 仍是已发布的旧版本；本地共用新源码已准备，需在用户验收测试结果后发布。操作台共享 Python 代码在本机立即生效。旧 Desktop 文件夹里的历史独立命令未被删除，请使用操作台入口。

## 未纳入本次的后续工作

- Google Sheet 多表写入仍非事务；需要批次存储及原子切换，才能在远端写入中断时可靠回滚。当前的本地备份和读回验收不代表解决这一点。
- UPB 仍全量读取历史 Excel；本次约 94 万条交易计算约 3 分钟。增量缓存需覆盖文件替换、映射变化及汇率变化的失效规则，再单独实施。
- Worker 的静态备用快照和跨地区缓存仍需独立版本化发布方案；本次改善的是同步核验和恢复，不能承诺所有地区即时更新。
- 个人目标分配、历史归属、完整日定义和活跃窗口属于业务规则，未擅自改动。
- 本次未更改网站访问权限、重做页面、添加 KYB 或迁移数据库。
