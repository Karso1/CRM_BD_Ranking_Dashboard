# 代理资料

代理排名和 API 排名的最右列显示合作开始日期，可点击表头排序。点击名字打开详情，显示归属 BD、类型、邮箱和完整合作开始时间。未填写的字段留空，空日期始终排在末尾。

## 数据来源

- UPB：原始数据中的 `BD代理关系目标/BD代理关系.xlsx`，含 `client`、`Categories` 和两个 `BD` 列的工作表。第二个 `BD` 列是唯一有效的 BD 名单。
- UPW：原始数据中的 `total data/代理关系及月份目标.xlsx`，含 `代理商`、`商务` 的工作表。
- 可选资料表头为 `邮箱`、`合作开始日期`（也支持 `合作开始时间`）。不自动把两个平台的同名代理关联起来。
- UPB 代理资料的归属与业务计算保持一致：名单内的 BD 使用名单标准名称；不在名单内的原始归属统一显示为 `UPay`，不会作为 BD 选项或搜索归属暴露。代理本身仍保留在名单中，零数据时也可展示。
- UPW 测试和正式环境采用相同公开 BD 白名单（Victor、Katrina、Ruslan、Mike、Patrick、Richard、Marketing）；其他原始归属统一显示为 `UPay`。零数据代理仍保留，补行去重也按显示归属合并，避免与已有数据重复。
- 日期优先保留 Excel 日期值；文本 `02/12/2024` 按日/月/年读取为 2024-12-02，不做时区转换。
- 相同名称、归属 BD、类型且邮箱一致的重复资料合并，合作时间保留最早的非空值。不同邮箱产生明确冲突，不自动覆盖。
- 原始 Excel 不会被同步程序修改。

## 更新流程

运行测试更新时，程序生成 `agent_profiles.json`，与每日汇总共同校验、发布到测试环境独立快照。资料输出纳入测试验收哈希，验收后变更会使发布校验失败。真实邮箱不写入前端源码、静态备用数据或 Git。

登录后的管理员可以读取这些联系方式；BD 账号仅能读取其授权 BD 范围内的代理资料。用户已验收测试环境，并于 2026-09-28 批准同步到正式环境。

测试与正式同步使用同一套资料发布逻辑，但分别写入独立的环境快照。首次发布须先部署支持资料的新 Worker，再发布验收过的数据；后续继续使用“测试更新 → 验收 → 正式发布”的流程。
