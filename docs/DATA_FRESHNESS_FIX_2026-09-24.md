# 数据刷新与首屏恢复验收

## 已修复并部署

- 正式站首屏立即显示本地快照；实时读取期间或失败时，会标出快照截止日期并提供重试，不再整页卡在加载页。
- UPB、UPW 正式同步配置使用同一个 WalletSync Apps Script；该接口同时返回两套数据。Worker 现在优先从 `WALLET_SOURCE_URL` 读取两套数据，避免 Business 看板继续读旧的 `DASHBOARD_SOURCE_URL`。
- Worker 冷读超时从 12 秒调整为 55 秒，前端请求上限为 65 秒。生产 Business 接口实测一次冷读约 47 秒。
- 浏览器每 30 秒轮询；同步程序使用 `refresh=1` 绕过 Worker 缓存，写入成功后立即重新填充当前数据中心的缓存。普通请求仍可使用 10 分钟缓存。
- 默认日期会随成功读取到的最新日期前进；用户手动选择历史日期时保留选择。

## 仍需持续改进

- Cloudflare Cache API 按数据中心缓存。冷数据中心仍可能等待 Apps Script 重新计算；本次页面可以先显示快照，但没有实现全球缓存预热或批次版本发布。
- 约 47 秒的冷读偏慢。后续可将同步后的已验收 JSON 保存到稳定存储（例如 Cloudflare R2/KV），让网页请求只读取成品，而不是现场重算整本 Google Sheet。
- 页面轮询是兜底，不代表源数据已更新；日常仍应运行 UPB/UPW 同步命令，并确认终端的“网站缓存已更新 / 同步完成”验收信息。
