# 网站访问用户名和密码

测试网址：https://upay-bd-ranking-staging.karsol.workers.dev
正式网址：https://upay-bd-ranking.karsol.workers.dev

打开网站先输入共用用户名和密码。默认英文，可在登录卡片右上角切换中文。无需注册个人账号或邮箱。正确后直接进入原有看板，同一浏览器保持登录 7 天；登录页不显示此说明。看板右上角的退出按钮可以提前退出。

## 查看当前密码

测试站打开 `tools/daily-operations/01-测试更新/测试网站访问密码.local.txt`；正式站打开 `tools/daily-operations/02-正式发布/正式网站访问密码.local.txt`。首次发布时两站使用相同的用户名和密码，之后可分别修改。文件仅保存在这台电脑，权限仅限电脑当前用户，并已排除在 GitHub 上传之外。

## 修改密码（推荐）

1. 打开要修改的网站对应的 `tools/daily-operations/01-测试更新` 或 `tools/daily-operations/02-正式发布` 文件夹。
2. 双击 `修改网站用户名和密码.command`。
3. 输入新用户名（直接回车保留当前用户名），然后输入新密码并按 Enter，再输入一次密码确认。密码输入时终端不显示字符，这是正常现象。若只改用户名，两次密码都输入当前密码即可。
4. 等到“网站已接受新密码，生效检查通过”即完成；至少使用 12 位密码。关闭窗口，打开对应网站并使用新密码。

这仅会更新所选网站的登录密钥，无需重新跑 UPB/UPW 或重新上传数据。Cloudflare 发布传播通常需要几秒，工具会等待并检查新密码。生效后，原来已登录的浏览器在下一次访问或网页自动检查数据时会要求重新输入密码。另一个环境不受影响。

如果已经显示“密码已保存”，但网站生效检查暂未通过，密码记录已更新，请稍后用本地文件里的新密码访问，不要反复改密。

电脑需要能够连接 Cloudflare，并保留当前 Cloudflare 登录。若提示未登录，请联系维护者重新授权后再执行。请把新密码告知需要访问的同事。

## 也可以在 Cloudflare 修改

登录 Cloudflare → Workers & Pages → 对应的 **upay-bd-ranking-staging**（测试）或 **upay-bd-ranking**（正式）→ Settings → Variables and Secrets，编辑 **DASHBOARD_USERNAME**（用户名）或 **DASHBOARD_PASSWORD**（密码），类型均保持 Secret，保存并部署。用户名或密码任一修改后，旧登录都会失效。

不要修改 `DASHBOARD_SESSION_SECRET` 或同步数据所用的其他配置。在控制台修改后，本地密码文件不会自动更新，可重新运行双击入口设置最终密码并更新本地记录。使用双击入口可避免忘记更新本地记录。

## 实现与验证口径

密码由 Worker 验证，保护页面、数据接口和包含备用数据的静态脚本。浏览器只保存有期限的签名登录 Cookie（HttpOnly、Secure），不保存明文访问密码。登录尝试按 IP 限速；改密码后旧 Cookie 无法继续访问。登录页不加载业务数据。没有配置密码时会拒绝访问，不会自动公开。

UPB/UPW 更新程序继续使用原有独立同步密钥。网页访问密码不会赋予写入业务数据的权限。

首次配置测试站使用维护命令 `python3 tools/site-access/change_password.py --initialize`；正式站首次发布可使用 `python3 tools/site-access/change_password.py --environment production --copy-staging`，使用同一账户但生成独立会话密钥。日常只用对应文件夹的双击入口改密码。

已获准查看过的数据无法从别人保存的文件、截图或以前下载的内容中收回；访问控制保护启用后的请求。目前测试站与正式站均启用后台验证。
