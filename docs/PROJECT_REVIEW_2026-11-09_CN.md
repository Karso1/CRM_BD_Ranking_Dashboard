## 后续优先事项

1. **发布可追溯**：给每次网站发布保存 Git 提交、构建编号和环境信息；当前已部署内容包含尚未提交的代码，单看 Git 无法准确复原线上版本。
2. **减少漏步骤**：提供统一操作入口，分别显示“已下载、已导入、测试已更新、生产已发布”的截止日期。下载完成不能等同于网站更新完成。
3. **客户导入并发控制**：当前客户存储是 KV 的读取—合并—写入；两人同时导入可能互相覆盖。正式推广到多人操作前，应增加串行写入或事务存储，再加入操作者、导入批次与回滚记录。当前单个上一快照不等同于完整审计历史。
4. **配置与运行监控**：生产/测试构建环境和 KV 已分离，建议补充结构化失败日志、请求耗时与告警；当前配置未显式启用完整日志/追踪。保持业务明细与密钥不进入日志。
5. **继续降低浏览器依赖**：UPW 仍依赖后台页面结构，既有恢复测试通过不代表以后页面改版不会失效。后续有稳定导出接口时再替换采集层，保留导入校验、备份及发布验收。
6. **拆分展示与计算**：继续把 `app/page.tsx` 中的统计计算拆成纯函数，扩大日期切换、负数退款、跨月目标与账号切换的回归覆盖，逐步加入真实浏览器自动验收。
