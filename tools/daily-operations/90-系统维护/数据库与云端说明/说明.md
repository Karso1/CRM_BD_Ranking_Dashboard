# 数据库与云端服务位置

本地操作台把数据库相关说明集中在这里，但数据库本身不是本地文件：正式与测试数据分别保存在各自独立的 Google Sheets；Apps Script API 和 Cloudflare Worker 也分别部署在各自的云端项目中。

## 环境对应关系

| 环境 | Google Sheets | Apps Script API | Cloudflare Worker |
| --- | --- | --- | --- |
| 正式 | 现有生产数据库（Google Sheet） | 正式 Apps Script 项目 | `upay-bd-ranking` |
| 测试 | `UPay Dashboard Staging Database - Test Data` | `UPay Dashboard STAGING API` | `upay-bd-ranking-staging` |

测试网站现在同样需要登录，管理员与 BD 账号按角色读取数据。原始订单/卡片导出和密钥不发布。测试更新只使用 `01-测试更新` 中的启动器写入独立测试表；不要手动复制生产表 ID、访问密钥或原始客户明细。

## 本地代码与配置

- Apps Script 源码可从上一级的 `Apps Script 源码` 快捷入口查看（实际代码仍维护在仓库 `google-apps-script/`，不是复制件）。
- Worker / 网站代码和部署配置在仓库根目录及其 `wrangler` 配置中。
- 同步程序的本地密钥配置放在各 pipeline 目录的 `sync.local.json` 或 `sync.staging.local.json`（Git 忽略）。不要把密钥复制到此说明、截图或聊天中。
- 测试输入目录由 staging 启动流程从原始数据入口刷新；测试站虽然需要登录，仍按真实敏感数据管理。原始数据入口见 `../../03-原始数据/`。

## 更新提醒

日常同步只更新对应 Sheet 与网站数据，不需要重新部署网站或 Apps Script。只有代码、接口或数据库结构变更时，才按测试环境流程验证，然后分别发布正式服务。正式与测试配置不要互换。
