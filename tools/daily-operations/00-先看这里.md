# UPay 每日操作｜只看这一页

你平时只需要记住：**先测试，确认没问题，再发布正式数据。**

## 每次更新数据

1. 把新导出的文件放进 `03-原始数据` 里对应的 UPW 或 UPB 文件夹。
2. 打开 `01-测试更新`，只双击你这次更新的平台：`UPW-测试更新` 或 `UPB-测试更新`。等窗口显示完成，再检查测试网站。
3. 测试网站上的日期和数据都正确后，打开 `02-正式发布`，双击同一平台的 `UPW-正式发布` 或 `UPB-正式发布`。

**如果测试结果不对或程序报错：不要发布正式数据。** 把窗口截图发给我；如果只是网站读取超时，可以按我指导去 `04-出错时再看` 运行“重新核验”。

## 这几个文件夹是做什么的

- `01-测试更新`：先把新数据更新到测试网站。
- `02-正式发布`：只把已经在测试环境验收通过的数据发布到正式网站。
- `03-原始数据`：放后台导出的原始文件；里面的两个入口仍指向你原来的数据文件夹，没有搬走或复制你的数据。
- `04-出错时再看`：只有遇到超时或报错时才打开；里面有核验入口和运行记录。
- `90-系统维护`：程序和技术说明，平时不用打开，也不要移动里面的文件。

## 网站功能改动和日常数据更新不是一回事

每天更新数据时，按上面的测试→发布流程即可。若要改网站页面或计算程序，先由 Codex 更新并部署测试环境；你验收后，再由 Codex 把同一版代码发布到正式环境。**不要用“正式发布”文件夹来发布网站代码。**

测试站的账号只用一个入口：在 `01-测试更新` 双击 `账号管理.command`，先选“新增”或“修改”，再选“管理员”或“BD”。BD 必须绑定程序列出的实际 BD 名称；管理员可查看全部数据。密码输入时终端不显示字符。账号修改不需要重新跑数据程序。账号记录仍保存在本机，不会上传 GitHub。详见 `docs/BD账号测试说明.md`。

正式站目前仍只有原 UPay 账号；修改正式站账号时，在 `02-正式发布` 双击 `修改网站用户名和密码.command`。两个环境互不影响。详见 `docs/网站访问密码说明.md`。
