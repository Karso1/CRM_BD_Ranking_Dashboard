# UPB 数据下载与补齐

双击桌面操作台 `01-下载数据/01-UPB-下载及补齐数据.command`。菜单默认选项会从首次成功下载的日期一直检查到 UTC+0 的昨天，自动补齐缺少的日期；已经完整保存的日期会校验并跳过。如果几天没有上班，回来后直接选默认项即可。也可以选单日或自行输入起止日期。首次使用会打开独立的 Chrome 窗口，请在该窗口登录业务后台，并按终端提示继续。后台验证码由本人完成。此工具不读取平时 Chrome 的密码或 Cookie。

每个选中日期都下载 UTC+0 的 00:00:00–23:59:59，按日保存，不追加月度 Excel，不自动发布网站。程序按日期从早到晚逐日处理；中途失败时，此前已完整保存的日期保留，重新运行可继续补齐。超过 7 个待下载日期时，程序会显示至少需要多少个后台导出任务，并要求输入「继续」确认。

| 数据 | 日期条件 | 原始数据目录下的位置 |
| --- | --- | --- |
| 开卡 | 申请时间 | 开卡/每日自动下载/YYYY-MM/开卡_YYYY-MM-DD.xlsx |
| 充值 | 创建时间 | 充值数据/每日自动下载/YYYY-MM/充值_YYYY-MM-DD.xlsx |
| Passto | 主订单＋更新时间 | 消费数据/每日自动下载/YYYY-MM/Passto_YYYY-MM-DD.xlsx |
| Reap | 主订单＋更新时间 | 消费数据/每日自动下载/YYYY-MM/Reap_YYYY-MM-DD.xlsx |
| StraitsX | 主订单＋交易时间（后台没有更新时间筛选） | 消费数据/每日自动下载/YYYY-MM/StraitsX_YYYY-MM-DD.xlsx |
| 手动开卡 | 卡片状态＝激活/绑定/开卡成功；全量快照，不按天筛选 | 手动开卡/手动开卡-最新.xlsx |

原始数据目录沿用操作台 `03-原始数据/UPB每日数据` 指向的位置，目前为 `/Users/admin/Desktop/upay/UPB每日数据`。现有计算程序会递归读取这些每日文件，并执行原有订单去重规则，无需手动合并。

手动开卡用于卡 ID 到代理商的归属映射，不参与每日开卡张数计算。每次正常运行下载程序时，只导出一次“激活/绑定/开卡成功”的全量快照，即使五类每日文件已经下载完成也会刷新它；补齐多日不会重复导出多次。程序核对后台总条数、Excel 行数、必需表头、成功状态及用户卡片 ID 后，先把原来的唯一 Excel 备份到 `.local/manual-backups/`，再替换为固定文件名 `手动开卡-最新.xlsx`。后台列表数可能比直接导出的成功记录少一条；此时只接受导出行数不少于列表数、差异不超过 10 行，且逐行符合成功状态、卡 ID 不为空。目录中如果有多份 Excel，或条数超过安全导出上限，程序会停止替换，要求人工核查。

手动开卡查询会等待“重置”和表格加载完成，并确认成功状态筛选及首行状态。页面短暂显示 0 条时会重新搜索，最多 3 次；持续为 0 条则停下核对后台和账号权限，不覆盖旧表。

程序清除页面默认日期条件，再设置对应日期，并明确选择主订单。指定多日时按日期从早到晚处理，**不会把整个历史范围作为一次导出**。单份导出达到 18,000 行时（低于已知的 20,000 行限制），会把当天时间区间继续二分，直到每份导出低于阈值，再校验各文件、合并为当天文件；如果单秒仍超限或数量对不上，则停止，不导入可能缺漏的数据。后台页面条数有时更新滞后，异步导出以任务行数和实际文件行数核对；StraitsX 还要求每段页面条数与文件行数相同。

每天的五类文件先暂存并核对表头、日期、订单类型和行数，全部通过后才复制到原始目录。手动开卡快照先下载并校验，待每日任务完成后才备份和替换旧表。相同日期的每日文件成功下载后，再次运行会校验文件哈希并跳过。遇到已有同名每日文件、错误日期或导出失败时停止，不静默覆盖。中途失败时，前面已经完整保存的日期保留，再次运行会跳过它们。

以前的下载可能混有子订单；不要把旧文件视为符合新规则。已完成日期若需修复，可以用 `--repair-date YYYY-MM-DD` 重下三个渠道：程序会先备份旧文件和完成记录，再替换三份渠道文件；开卡和充值保持不变。备份保存在 `.local/repairs/`，修复不更新网站。

下载完成后，双击原有 `UPB-测试更新.command` 计算并更新测试网站，确认后使用 `UPB-正式发布.command` 发布。请勿在下载期间另行直接启动计算脚本；通过标准测试入口运行时，安装文件阶段与测试更新共用锁。

命令行指定单日或日期范围：

```bash
tools/upb-download/.venv/bin/python tools/upb-download/download.py --date 2026-10-15
tools/upb-download/.venv/bin/python tools/upb-download/download.py --start-date 2026-10-13 --end-date 2026-10-15
tools/upb-download/.venv/bin/python tools/upb-download/download.py --repair-date 2026-10-15
```

仅检查路径和范围：追加 `--dry-run`，不会打开后台或下载文件。

登录状态、下载暂存文件和完成记录保存在此目录的 `.local/`，已被 Git 忽略；不要上传或分享该目录。程序不设置定时任务，电脑关机时不会运行。浏览器会话过期时会提示重新登录。

开发依据：[Playwright 浏览器上下文](https://playwright.dev/python/docs/api/class-browsertype#browser-type-launch-persistent-context)及[下载处理](https://playwright.dev/python/docs/downloads)。

验收记录：2026-10-15 至 2026-10-17 三天已按新规则完成五类文件校验；其中 2026-10-15 的三个渠道旧文件已备份并修复，StraitsX 的连续分段导出已在实际后台验证。网站测试、正式环境未随下载自动更新。首次登录或会话过期后仍需本人在弹出的浏览器中重新登录。
