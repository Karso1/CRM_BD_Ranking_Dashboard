# UPW 原始数据导入

UPW 后台目前只允许使用已经登录的 Chrome，会拒绝独立浏览器会话。因此本目录的独立浏览器下载脚本默认禁用。日常流程是：在原有 Chrome 使用扩展导出 → 双击 `02-UPW-校验并导入数据.command` → 测试环境更新与验收 → 正式发布。双击导入入口时，校验通过会自动备份、安装原始数据并同步日期清单，**无需输入“导入”**；校验失败停止。网站仍需后续更新。

导出范围按后台 UTC+8 日期：

1. 用户卡片：`卡状态 = 申请成功`，导出全量。超过 1 万条时需要分段方案，当前导入器会拒绝单文件行数不符。
2. 交易记录：`状态 = 已完成`，`交易提交时间 = 待补日期 00:00:00–23:59:59`，逐日导出；每天超过 1 万条按导出弹窗分段。
3. 用户代理关系：从最新的 `1–10000` 段开始，必要时继续下载后续段，直到与历史 UID 重叠。记录弹窗显示的总条数。

把页面条数、日期及下载文件绝对路径写入本机 JSON 清单。格式示例：

```json
{
  "as_of": "2026-10-19",
  "cards": {"path": "/Users/admin/Downloads/cards.csv", "count": 8332},
  "relationships": {
    "total": 132301,
    "segments": [{"path": "/Users/admin/Downloads/relationships-1.csv", "count": 10000}]
  },
  "transactions": [
    {"date": "2026-10-19", "count": 1747,
     "segments": [{"path": "/Users/admin/Downloads/transactions-2026-10-19.csv", "count": 1747}]}
  ]
}
```

`transactions` 必须覆盖原始数据中缺失的每一天；示例只说明格式，不能直接当作每日清单。先校验，再明确安装：

```bash
python3 tools/upw-download/import_exports.py /path/to/manifest.json
python3 tools/upw-download/import_exports.py /path/to/manifest.json --install
```

程序校验表头、页面/文件行数、成功或完成状态、每行日期、订单号及卡 ID 唯一性，并确保新关系段和历史表重叠。全部通过后，才会备份旧卡片快照并安装原始 CSV；历史关系 Excel 不改写，新增关系写入 `代理关系增量.jsonl`。`.local/backups/` 保留旧快照。若当天确实是零交易，当前导入器会停止，需要人工确认后再补充零交易日记录功能，不能悄悄跳过。

专用扩展已经提供，安装目录为 `chrome-extension/`，不要选择外层 Python 目录，否则 `__pycache__` 等文件会导致 Chrome 加载失败。当前版本 0.3.7，在页面中显示可拖动、可收起的面板；权限与版本行为见扩展 README。独立浏览器不是 UPW 的日常入口。

扩展已在现有 Chrome 重新加载并有部分真实导出验收；完整新流程仍需连续真实后台运行验证，不能仅凭单元测试宣布长期稳定。更新源码后需在 `chrome://extensions` 重新加载原扩展并刷新后台页面。

扩展的“1. 自动补齐缺少日期”使用本地 `UPW-已导入日期.json`。首次在扩展中选择桌面操作台 `01-下载数据/upwdownload/` 内的这份文件。成功用 `import_exports.py --install` 导入后，程序会同时刷新项目目录和桌面操作台中已存在的日期清单；单独运行 `python3 tools/upw-download/coverage.py` 也会同步两份。扩展每次自动补齐前会重读清单，并分别显示最新交易日期、清单生成日期、真正缺少的日期。清单生成日期不等于已导入截至日期。已安装扩展要在 Chrome 扩展管理页重新加载才能看到新版。文件选择会触发 Chrome 对单个本地 JSON 的读取授权，不增加扩展的网站权限。

导入校验时会预先生成本批日期清单；安装原始数据时一起写入并核对两份清单，然后才提示“导入完成”。清单写入异常会回退本次原始数据安装与已替换的清单，不再把清单失败作为导入成功后的普通警告。此前已导入数据但清单落后的情况可运行 `coverage.py` 修复，无须重复导入交易。
